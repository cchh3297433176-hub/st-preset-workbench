# 预设缝合与智能编辑：防遗忘专题（最高优先）

## 用户的原始痛点
用户在操作台中把 A 移到 B/C 附近，再把 C 移到 E/F 之间，**希望退出操作台或点击应用后才真正更新**；旧工具却每一步立即在后台更新，导致手机卡顿。另有条目从别的预设复制后**看似插入成功却不生效**，因为目标预设要求特殊格式、变量链、Role、深度、任务流程或包裹结构。用户还希望懂系统/用户 role、插入深度和完整输出格式，而不只是复制文本。

## 合并算法目标
1. 离线读取源/目标完整 JSON，建立规范化索引，但保留原始字段和未知扩展。
2. AI 识别源条目功能、目标预设对应的逻辑插槽及依赖（变量、格式、正则、脚本、角色/注入、思考模块）。
3. 输出迁移计划：保留原样 / 转换目标格式 / 增补依赖 / 建议替换 / 发现冲突需人工决策。
4. 在独立草稿中完成重排、插入、批量编辑；每一步仅改草稿内存，不触发 Tavern 保存和插件刷新。
5. 提供真实前后 diff、依赖图、实际消息预览、token 变化、风险提示。
6. 用户确认后原子式提交；保存前备份、提交后校验、失败可回滚。

## 具体兼容点
- `prompts` 存储顺序 ≠ `prompt_order` 启用顺序；同时存在多个 `character_id` 组时不能忽略。
- `system` / `user` / `assistant` 角色，marker 与普通 prompt，injection_depth/position/order 等元数据不能丢。
- 变量 `setvar`、`addvar`、`getvar`、`getglobalvar`、初始化清空、trim、局部/全局作用域及 QR 依赖。
- XML/Markdown/自定义标签的成对结构、写作思考、输出格式和状态栏/正则处理的链路。
- `extensions.regex_scripts` 与 TavernHelper `extensions.tavern_helper`、柏宝箱等；不要只合并 prompts。
- 插件脚本迁移时禁止自动执行未知 JS；检测网络加载器和外部资源。

## 作者更新三方合并
输入 A=作者旧版，B=用户改过的旧版，C=作者新版，输出 D。先按稳定 identifier 匹配，再用名称/内容相似度作为候选，不自动把相似条目视为相同；识别用户重排、作者重排、改名、删除、拆分；冲突可选保留 A/B/C 或手动编辑，保留 provenance。

## MVP 验收用例
- 从 Ako 抽取一个变量依赖模块，移入另一套不同变量命名/格式的预设；能提示缺失依赖并生成经确认的修复草稿。
- 批量移动十条后，原预设在确认前完全不变；确认后一次写入。
- 修改作者旧版，再导入作者新版，保留用户修改并报告真实冲突。
- 关闭写入变量的条目时，自动提示对应读取模块可能收到空值或旧值。
- 预设包含脚本/正则时，迁移不静默丢字段。
