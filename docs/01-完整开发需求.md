# 完整开发需求（讨论结论，非已实现功能）

## 1. 产品与工作流
- 多会话 AI 助手，能读现有预设、讲解条目、提出改动计划、批量编辑、从零创建完整预设；支持从自然语言目标生成可导入 SillyTavern 的预设。
- AI 可选择不同作者预设作为参考，但不得机械套用单一作者结构。语义功能分类与真实 prompt_order 分开展示。
- 多源导入：本地 JSON、原有预设、角色卡/世界书关联数据、扩展元数据；导出完整包并尽量保留未知字段。
- 手机端：独立草稿状态、局部更新、虚拟列表、搜索/过滤、批量移动、折叠条目、操作历史、差异预览、一键确认提交。

## 2. 编辑与迁移
- 条目增删改、启停、移动、排序、角色 role、注入位置与深度、分组、批量修改。
- 智能跨预设缝合：移植内容时识别目标的 XML/Markdown 包裹、变量初始化和读写、任务流程、输出格式、思考模块、角色与深度要求；给出兼容方案并检测依赖。
- 正则跨预设迁移、冲突检测、隐藏/显示、匹配测试；注意世界书绑定正则和状态栏生成器联动，避免复制运行副本造成重复。
- TavernHelper 脚本树与扩展：保留 folder/script、id、enabled、content、button、data、export_with；默认静态分析，不执行第三方代码；网络加载器需另行获取/验证源代码。
- QR/变量迁移：分析局部/全局变量、读写与作用域、覆盖、初始化、条件分支、失效引用；提示缺失和循环/冲突。

## 3. 预设版本升级
- 三方合并：旧作者版 A、用户修改版 B、新作者版 C，得到保留作者更新和用户自定义的 D。
- 识别条目改名、重排、拆分、合并、角色与深度改变、启停改变；冲突可逐项审阅，保留原始备份。
- GitHub 或远程保存失败时不能丢失本地工作；检查保存结果，允许恢复。

## 4. 运行时与实验
- 区分 JSON 存储顺序、prompt_order 排序、宏展开、worldInfoBefore/After、角色卡、persona、scenario、chatHistory、In-Chat 深度注入、正则及扩展的实际影响。
- 最终 API 消息检查器：role、顺序、深度、来源、变量展开结果、token 估计及实际请求对照；能解释为何某条目没有被发送。
- 测试实验室：固定角色/世界书/场景/模型/随机参数，对比文风、剧情、格式遵守、角色一致性、耗时与 token；实验数据有来源与版本。

## 5. AI 与模型适配
- 尽可能复用现有 SillyTavern 模型/API 配置，是否能安全复用必须验证；也可独立配置 OpenAI 兼容 API、手填模型、连接测试。
- 预设架构：通用核心 + 具体模型/版本适配层 + 作者独特模块；支持版本迁移，避免将 Gemini/DeepSeek/Claude 混为一类。
- 知识管理：核心小提示词 + 按任务检索经验卡 + 按需展开原始资料；经验开关、模型版本、来源、证据、时效、测试状态、token 预算。

## 6. 安全和交付
- 提交前审查、差异、备份、回滚；并发修改检测；未经授权不得写用户文件或仓库。
- 不随意执行外来 JS、远程加载器或宏副作用；必要时沙箱静态分析。
- UI 风格由用户审核，先设计后编码；服务器 UI Skill/风格参考位置仍待查。
- 需要明确 MVP 与后续阶段，避免一次性开发过大。
